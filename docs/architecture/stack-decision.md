## 선택 기준
1. **콘텐츠 중심**: 약 1,500자 이야기, 활동 지표, 프로젝트 및 문서가 핵심이다.
2. **접근성과 검색성**: 최초 HTML 렌더링, SEO, 시맨틱 마크업, 모바일 성능.
3. **부분 인터랙션**: 날짜 필터, 단계별 이야기, 확장 패널 등만 동적으로 동작해도 충분하다.
4. **정적 배포**: 로그인/DB/서버 API가 필수 요구사항이 아니다.
5. **결정적 재생성**: Python 등의 오프라인 도구가 사용자 승인된 JSON/콘텐츠를 생성하고 사이트가 읽는다.
6. **미래 확장**: T13 앱 연결은 필요하지만, 사이트 자체가 인증/데이터베이스를 요구하지 않는다.
7. **개발 경험**: 기존 TypeScript/React 경험 활용과 새로운 도구 학습 사이의 비용을 비교한다.

## 후보 A — Astro + TypeScript + CSS (+ 필요 시 React Island)
장점:
- 정적 콘텐츠 중심에 최적화되어 브라우저로 내려가는 JavaScript를 작게 유지하기 쉽다.
- HTML 기반 SEO 및 페이지 로딩 성능 관리가 명료하다.
- 필요한 컴포넌트만 React 등으로 수화하여 풍부한 상호작용을 추가할 수 있다.
- 구조화된 콘텐츠 컬렉션을 통해 날짜/프로젝트/증거 데이터를 관리하기 편하다.

단점:
- 기존 Next.js/React와 다른 템플릿·콘텐츠 흐름을 익혀야 한다.
- 화면 대부분이 복잡한 React 상태를 공유하게 되면 Island 경계 설계가 번거로워진다.
- 동적 서버 기능이 늘어날 경우 아키텍처를 확장해야 한다.

## 후보 B — Next.js App Router + TypeScript + React + CSS
장점:
- 기존 T01/T06/T07 경험과 익숙한 구조 재사용에 유리하다.
- React 생태계와 컴포넌트/라우팅 기능이 강력하다.
- 차후 서버 기능, 인증, API가 정말 필요해지면 같은 체계에서 확장할 수 있다.
- 정적 빌드(조건부) 가능.

단점:
- 본 과제에 불필요한 프레임워크 구성 요소와 서버/클라이언트 경계 개념이 늘어날 수 있다.
- 정적 export에서는 서버 동적 기능 등 사용에 제한이 있다.
- 단순 콘텐츠 중심 사이트 대비 운영·빌드 복잡도가 높을 수 있다.

## 후보 C — Vite + React + TypeScript + CSS
장점:
- React 개발 경험을 그대로 활용하면서 빠르게 시작할 수 있다.
- 인터랙션과 컴포넌트 상태가 많은 포트폴리오를 표현하기 쉽다.
- 정적 호스팅과 빌드 출력 구성이 단순하다.

단점:
- 기본 SPA에서는 첫 요청 HTML에 콘텐츠가 충분히 제공되지 않을 수 있어 SEO 및 초기 표시를 보완해야 한다.
- 라우팅, 메타데이터 관리, 문서 콘텐츠 체계는 별도 설계가 필요하다.
- 단순 읽기 위주 페이지에도 JS 번들이 필요하다.

## 후보 D — Eleventy(11ty) + 템플릿 + CSS/소량 JS
장점:
- HTML 중심의 정적 사이트 제작에 적합하며 런타임 JavaScript 부담이 적다.
- 콘텐츠와 생성 로직이 단순하고 배포 플랫폼에 덜 종속된다.
- 브라우저 JavaScript 없이도 대부분의 요구사항을 충족할 수 있다.

단점:
- React/TS 컴포넌트 중심의 기존 개발 습관과 다르다.
- 고도화된 인터랙션·애니메이션은 수동 JS 설계의 비중이 커진다.
- 디자인 시스템과 타입 검증을 일관되게 유지하려면 추가 규칙이 필요하다.

## 확정 결정 (ADR-001)
사용자 선택에 따라 **Next.js 16.3.8 App Router + TypeScript + React 19.2.8 + 일반 CSS**로 확정했다.

- 디자인 방향: **인터랙티브 실험형**
- 렌더링: 정적 HTML을 우선 제공하고, 탭·스크롤 인터랙션만 Client Component에서 실행
- 배포: `output: "export"`로 정적 내보내기. 서버 API·DB·인증은 과제 필수 범위에 포함하지 않는다.
- 데이터: 승인된 공개 정보만 `src/content/public-profile.ts`를 통해 노출
- 제약: 정적 export에서 서버 동적 기능, 서버 액션 등을 사용하지 않는다.
- 검증: `npm run check` 또는 CI에서 lint, 타입 검사, 콘텐츠 계약 테스트, 공개 소스 스캔 및 정적 빌드 수행
- 미검증 상태: 설치·빌드·접근성·시크릿 창 접속은 실제 실행 후에만 통과 처리

**대안 검토 기록:** Astro는 콘텐츠·성능에는 유리하지만 기존 React 숙련도와 동적 UI 구현 편의성을 고려해 선택하지 않았다. Vite SPA와 Eleventy도 SEO/인터랙션 개발 부하를 고려해 보류했다.

## 데이터와 승인 흐름(프레임워크 무관)
```text
[비공개: 리추얼/출석/제출 원본]
          │
          ▼
[오프라인 결정적 생성기]
          │ 산식/근거/문단 후보
          ▼
[로컬 검토 → 명시적 승인]
          │ 승인된 내용만
          ▼
[공개용 최소 JSON/Markdown + 3종 문서]
          │
          ▼
[정적 사이트 빌드 → HTTPS 배포]
```

### 비공개 데이터 정책
- `ritual-history-2026-10-21.json` 원본은 **공개 Git 저장소에 커밋하지 않는다**.
- 동료의 이름, 연락처, 원문 대화 및 비밀값을 공개용 산출물에서 제외한다.
- 미확인 출석 수와 승인 상태는 추정하거나 리추얼 일수로 대체하지 않는다.
- 공개 후보 문단은 AI가 자동으로 게시하지 않고 소유자의 수동 승인을 거친다.
