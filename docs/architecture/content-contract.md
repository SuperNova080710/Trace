# Trace 콘텐츠 경계와 승인 흐름

## 프로젝트 경계

- Next.js App Router / TypeScript / React / CSS.
- 프로젝트의 현재 배포 모델은 `output: "export"`를 통한 정적 결과물(`out/`)이다.
- 정적 배포이므로 요청 기반 API, 서버 액션, 인증, 동적 이미지 최적화는 지원 대상으로 다루지 않는다.
- `src/content/public-profile.ts`는 **승인된 공개 사실**만 보유한다.
- 개인 원본(리추얼, 출석표, 제출 현황)은 개발 환경의 `data/private/`에 따로 두고 Git에 넣지 않는다.

## 게시 파이프라인

1. `data/private/`의 입력 → Issue #7에서 만드는 Python 결정적 갱신 장치.
2. 장치가 후보 문단/집계를 작성하더라도 기본 `status`는 `pending`.
3. 사용자가 근거·날짜·개인정보를 확인한 후에만 `approved`가 된다.
4. 승인된 최소 필드만 `src/content/`에 복사 또는 생성한다.
5. 사이트 렌더링에서 `approvedOnly()`로 미승인 콘텐츠를 필터링한다.
6. 빌드 결과(`out/`)에 원본 파일이나 제3자 이름이 없는지 별도 검사한다.

## 설계상 주의

- Git ignore는 **추적되지 않은 파일**의 신규 추가를 방지할 뿐이다. 이미 커밋된 민감정보를 복구하지 않는다.
- 패턴 스캔은 보안 감사를 대체하지 않는다. 개인정보, 실명, 비밀값을 최종 수작업으로 점검해야 한다.
- 리추얼 기록 날짜 수와 실제 출석 일수는 서로 다른 지표이다.
- BR-A 첫·마지막 서사 문장은 반드시 오리온 본인이 작성하고 최종 승인한다.
- 연락용 공개 이메일 `lionoh00@gmail.com`은 사용자 제공 정보로 게시가 승인되었다.
