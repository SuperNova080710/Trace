# Issue #3 UI·접근성 확인 절차

대상: `issue-3-portfolio-ui` 브랜치 · Next.js 정적 포트폴리오

## 적용 범위

- 모바일 내비게이션: 기존에 숨겨지던 기록/연락 메뉴 대신 열기·닫기 버튼, 모든 섹션 링크 제공
- 키보드: Tab/Shift+Tab으로 메뉴 접근, Enter/Space로 토글, 메뉴에서 Escape 시 닫고 버튼으로 포커스 복귀
- 히어로: T09에서 출발한 ‘…하는 사람’ 형태의 한 줄 소개 및 하단 연락처로 이동하는 공개 이메일 표시
- 소개·프로젝트·기록·지원 서류로 빠른 이동
- 지원 서류는 아직 #6에서 제작 전이므로 상태만 보여주고 가짜 다운로드 링크를 표시하지 않음
- 승인된 서사 및 대인관계력 보완 표시 보존
- `prefers-reduced-motion`에 따라 스크롤/등장 애니메이션 감소, 장식 마우스 광원 비활성화

## 자동 검증

```bash
npm ci
npm run check
```

`check`에는 lint, typecheck, Node 테스트, 소스 검사, 정적 빌드, **최종 HTML의 필수 앵커 및 연락처 검사**가 포함된다.

## 실제 브라우저에서 추가 확인 필요

- [ ] 320px, 375px, 768px, 1366px 화면에서 가로 스크롤/텍스트 잘림 없음
- [ ] 모바일 메뉴 전개, 6개 링크 접근, 링크 클릭 후 메뉴 닫힘
- [ ] 메뉴에서 Escape 동작 및 키보드 포커스 복귀
- [ ] 상단 Contact/히어로 이메일 → #contact 이동, 하단 이메일 → mailto
- [ ] 스크린리더에서 메뉴 설명·탭·본문 섹션 제목이 자연스럽게 읽힘
- [ ] 시스템 모션 감소 설정에서 모든 본문이 정상적으로 보이고 필수 기능 사용 가능
- [ ] 색상 대비(특히 작은 텍스트)와 휴대전화 실제 터치 영역 확인
- [ ] Vercel 등 HTTPS 배포 후 시크릿 창 무로그인 접속 확인(#8 담당)

이 문서의 브라우저 수동 항목은 사용자가 실제 확인하기 전까지 PASS로 표시하지 않는다.


## 추가 수정 — 키보드 포커스 연속성

- [ ] Tab으로 아코디언 버튼에 포커스 후 Enter/Space로 열었을 때 윤곽선이 전체 펼친 항목을 둘러싸는지 확인
- [ ] 열고 닫는 애니메이션 중에도 윤곽선이 상세 내용의 크기를 따라가는지 확인
- [ ] 본문 중간까지 마우스 휠로 스크롤 후 Tab 시 상단 헤더가 아닌 현재 본문 주변이 포커스되는지 확인
- [ ] 위 상황에서 다음 Tab으로 정상적인 다음 링크/버튼으로 이동하는지 확인
- [ ] 이미 화면에 보이는 링크/버튼에서 Tab이나 Shift+Tab을 누르면 기존 브라우저 순서대로 동작하는지 확인
- [ ] 375px 모바일/모션 감소 모드에서 타임라인 및 아코디언 읽기/키보드 조작 유지 확인

읽던 위치 복귀는 이전 포커스가 화면 밖에 있고 스크롤 후 **정방향 Tab**을 누른 경우에 한해 동작한다. 
현재 화면의 컨트롤, Shift+Tab, Ctrl+Tab 등에는 개입하지 않는다.

## 아코디언 펼침 시 제목 위치 고정 (추가 수정)

열린 상태에서만 들어가던 `margin-block: 9px`과 1px 테두리 추가가 제목을 이동시키던 원인이었다.
닫힌 상태부터 전체 사방 테두리 1px을 확보하고, 열린 상태에서는 색과 배경만 변경한다.

- [ ] 마우스 클릭으로 열기/닫기를 여러 차례 반복해 선택한 제목 위치가 흔들리지 않는지 확인
- [ ] Tab 포커스 + Enter/Space 상태에서도 제목의 X/Y 위치가 변하지 않는지 확인
- [ ] 상세 영역의 높이 애니메이션과 포커스 테두리가 정상 작동하는지 확인
- [ ] 여러 항목을 연속 전환할 때 다른 항목도 예기치 않게 들썩이지 않는지 확인
