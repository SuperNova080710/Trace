# Issue #6 — 지원 문서 3종 검토·공개 승인 절차

## 현황 (2026-10-21)

- 이력서, 자기소개서, 프로젝트 경험기술서의 **검토용 PDF·DOCX**를 작업 환경에서 작성했다.
- 사용자에게 검토 파일을 전달하고, 사실·개인정보·채용용 표기 확인을 받기 전까지 **public/**, **src/** 및 GitHub 공개 브랜치에 업로드하지 않는다.
- 현재 웹 페이지의 `#documents`는 계속 **준비 중**이다. 공개 PDF 다운로드를 제공한다고 표시하지 않는다.
- 검토용 문서에는 학교/전공/졸업 시점, 지원 직무, 채용 서류에 사용할 명의가 확정되지 않은 상태임을 명시했다.

## 작성에 사용한 근거

- Trace Issue #2에서 사용자 본인이 최종 승인한 자기소개 본문, 첫·마지막 문장
- ALEPH T09에서 사용자가 직접 검토한 리추얼·캡스톤·문서화 경험
- T10 Native ECH 공개 소스의 **전체 Trial 200 / Held-out 110** 및 평가 JSON
- GitHub Blog Frontend/Backend 저장소의 구현 코드와 이슈 기록
- 2024 디지털 트윈 캡스톤 팀 과제(개별 역할·비공개 데이터 공개 금지)

## 사실·표현 제한

- T10은 **실험 연구 원고**이며 이전 Digital Twin 논문과 다르다.
- Held-out Recall은 두 탐지기 모두 1.0000, F1은 0.9091→0.9346, 정상 오탐은 10→7이다.
- 합성 단일 통제 환경의 결과를 실제 악성 트래픽/운영망 성능으로 확대하지 않는다.
- 기업 근무 경력, 졸업 날짜, 학위, 수상, 실사용자 수, 협업 기여율을 만들지 않는다.
- 공개 리추얼 원문·동료 실명·개인 출결 일별 상세를 포함하지 않는다.

## 사용자에게 필요한 결정

- [ ] 학교명, 전공, 학적/졸업(예정) 연월 확인
- [ ] 지원 직무 또는 채용 공고에 맞춘 문구 선택
- [ ] 채용용 문서에 사용할 이름(오리온 유지 / 실명) 결정. 실명은 공개 저장소에 자동 게시하지 않는다
- [ ] 3종 문서 내용과 본인 기여·역할 확인
- [ ] 공개 홈페이지에서 PDF 다운로드를 제공할 **범위와 명의**에 대한 최종 승인
- [ ] 필요하다면 연락용 전화번호 제공 여부 결정(미제공은 무방)

## 승인 후 제작·배포 순서

1. 사용자 확인 내용을 바탕으로 DOCX 3종 수정한다.
2. PDF로 렌더하여 한글 글꼴·줄바꿈·레이아웃·하이퍼링크를 점검한다.
3. DOCX/PDF 파일 이름을 명확히 정하고, **공개 승인된 파일만** `public/documents/`에 추가한다.
4. `src/components/trace-lab.tsx`의 준비 중 표시를 접근 가능한 다운로드 링크로 변경한다.
5. 정적 HTML·개인정보 스캔·익명 다운로드 및 자동 테스트를 검증한다.
6. Issue #5 PR이 main에 병합된 이후 최신 main과 충돌 없는지 확인하고, Issue #6 PR을 검토한다.

문서 원본의 일부 필드만 승인된 경우라도 전체 서류의 공개 승인으로 간주하지 않는다.
